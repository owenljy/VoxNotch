## 已确认并修复的问题

### 1. 短句被当作噪声丢弃

- 触发：约 256ms 的短回答，随后两帧静音。
- 原因：分句器已裁掉一帧静音，转写器却仍减去裁剪前的全部静音，导致有效语音长度被算成零。
- 修复：区分保留在音频中的静音和完整静音时长。前者用于噪声门限，后者用于延迟指标。手动 flush 也保留已知静音信息，并计入被丢弃的尾部采样，避免后续时间戳偏移。
- 回归：`UtteranceSegmenterTests`、`LiveTranscriberTests`。

### 2. 快速切换设备或开关音源后，旧任务重新打开采集

- 触发：系统音频权限/启动仍在等待时，停止、暂停、恢复或再次切换音源。
- 原因：多次操作覆盖同一个任务引用；旧的异步启动完成后仍可建立采集。失败后的流和 ingest 任务也没有完整清理。
- 修复：同一音源的启动串行执行，取消任务完成清理后才允许替换任务启动；在系统 API 的挂起点之后检查取消；启动/错误处理检查会话和音源操作代次。菜单栏切麦克风也走受控重启流程，面板在非运行状态禁用设备切换。
- 回归：`AlwaysOnCaptureCoordinatorTests`；Debug/Release 编译检查覆盖真实采集适配器。

### 3. 旧会话的转写、回答或错误污染新会话

- 触发：模型准备、VAD 或回答流尚未返回时停止并重新开始。
- 原因：旧回调直接操作共享状态；VAD 挂起期间被替换的 source pipeline 没有身份检查。
- 修复：会话 ID 和 pipeline ID 检查；流式回答检查请求所有权，停止时保存缓冲中的最后一批文字；重启、失败和清空面板时清理回答及自动触发任务。清空面板后不再遗留隐藏的手动回答阻挡后续自动回答。旧会话的收尾使用独立的历史转写状态。
- 回归：`AssistantServiceTests`、`LiveTranscriberTests`。

### 4. 停止或正常退出时丢掉最后一句

- 触发：说话尚未满足静音终止条件时按停止，或直接退出应用。
- 原因：立即取消 ingest 并清空待解码任务；退出也没有等待历史写入。
- 修复：停止采集后排空已收到的音频，flush 当前句子，等待最终解码和历史更新；正常退出使用 `terminateLater` 等待写入完成。重复停止不再改写已结束会话的结束时间。
- 回归：`LiveTranscriberTests.testFinishFlushesLastUtteranceAndWaitsForItsDecode`。正常退出的 AppKit 调用链经编译与代码检查，未自动驱动真实退出交互。

### 5. 删除的历史被延迟结果重新创建

- 触发：删除运行中或刚结束的会话后，转写/回答才完成。
- 原因：补建缺失 session 的逻辑无法区分“中途开启保存”和“用户已删除”；删除、改名与排队保存也不共享顺序。
- 修复：记录本进程中已删除的会话，拒绝后续恢复；保存、改名和删除统一排序，读取等待已提交的写入。
- 回归：`AlwaysOnHistoryStoreTests` 的删除单个、删除全部和未等待写入时改名用例。

### 6. 被撤销的预测回答仍留在历史中

- 触发：预测回答已快速完成并保存，随后对方继续说话。
- 原因：discard 仅删除界面中的回答；已完成的数据库记录没有删除。
- 修复：discard 同时按写入顺序删除历史记录；取消后的旧流不得再次保存。
- 回归：`AssistantServiceTests.testDiscardRemovesCompletedSpeculativeAnswerFromHistory`。

### 7. 手动回答后重复自动回答；关闭自动回答后定时器仍触发

- 触发：在 partial 阶段手动 Ask，然后该句定稿；或静音计时中关闭自动回答。
- 原因：手动 Ask 未标记当前句子已处理；静音定时器使用旧配置。
- 修复：记住手动处理过的 utterance；静音检查和实际触发时重新读取配置，暂停也重置触发状态。
- 回归：`AutoTriggerPolicyTests`、`AutoTriggerCoordinatorTests`。

### 8. 快捷键长按事件漏到前台应用

- 触发：长按 Ask 或回答翻页快捷键。
- 原因：首个 keyDown 被消费，重复事件却被返回给前台应用；keyUp 也未配对消费，重复分支还额外 retain 事件。
- 修复：追踪整个已消费的按键周期，重复事件和释放事件一起消费，处理函数每次按下只调用一次；非活动快捷键保持透传。
- 回归：`AlwaysOnShortcutTests`。

### 9. 两个音源重叠说话时转写乱序、错误拼接或保存错行

- 触发：一方长句尚未定稿，另一方短句先完成；切换麦克风后旧句结果较晚返回。
- 原因：按最终结果到达顺序追加，并允许负间隔合并。历史保存假定修改的一定是最后一行。
- 修复：最终句和 partial 按说话开始时间排序，仅按非负间隔合并，明确返回最近变动的最终行供历史保存。
- 回归：`AlwaysOnStateTests` 的重叠说话、partial 排序和旧设备结果用例。

### 10. 中途开启保存的会话缺少音源或结束信息

- 触发：会话开始时关闭保存，随后开启保存；或停止后的尾部结果才保存。
- 原因：补建 session 使用当前段落时间和空音源，无法恢复原始会话信息。
- 修复：会话元数据在内存中保留，后续需要落盘时使用原始起止时间、音源和关闭状态。
- 回归：`AlwaysOnHistoryStoreTests` 的中途开启和延迟保存用例。

### 11. Markdown 代码内容被错误处理

- 触发：使用 `~~~`、四个反引号包住三个反引号的示例，或代码里包含 `$PATH$`、`**`。
- 原因：代码围栏仅靠布尔值切换；公式清理和流式补全没有统一识别代码区域。
- 修复：匹配围栏字符和长度，在代码区域保留原文，补全正确类型的围栏，忽略代码里的强调标记。
- 回归：`MarkdownBlocksTests`。

### 12. 历史搜索及列表状态错误

- 触发：快速输入搜索词、刷新长会话或查看运行中的会话。
- 原因：旧查询可能覆盖新查询；每次重算时间线生成新 UUID；未正常关闭的运行中会话直接显示为崩溃恢复。搜索还会把全部片段与回答做组合连接。
- 修复：搜索任务随输入取消，并检查请求身份；列表使用记录的稳定 ID；恢复标签要求会话已经结束；查询改为 `EXISTS`，避免片段数乘回答数的中间结果。
- 验证：历史搜索测试覆盖片段/回答两张表、去重和字面通配符；全量编译和 SwiftUI 代码检查。未做真实大历史库性能基准或自动界面交互测试。
